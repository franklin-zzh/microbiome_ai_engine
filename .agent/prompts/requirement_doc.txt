项目需求确认文档（MVP）
生成时间：2026-07-29

## 一、项目定位
为「肠菌检测 + 调养」业务搭建“1 个统一知识底座 + 3 类角色 Agent”的轻量级 AI 矩阵平台：
- 客服 Agent（To-C 智能客服）
- 销售 Copilot Agent（To-B 企微侧边栏话术推荐）
- 医师 CDSS Agent（预留扩展，MVP 阶段仅做标签预留）

## 二、核心数据底座
单一事实来源：MySQL 8 单库 `mb_ai_engine`（2026-08-04 修订：原 PostgreSQL 已弃用，双库 mb_ai_core/mb_ai_cs 已合并；Dify 自带 pg 仅作元数据库、向量库用 Weaviate；表结构由 Alembic 迁移管理）。
- `core_*` 知识库体系：core_knowledge_items / core_unanswered_questions / core_sales_cases
- `cs_*` 客服会话体系：cs_chat_logs / cs_session_state / cs_leads_preview

## 三、Agent 与 RAG 配置
- 引擎：Dify（私有化 Docker / SaaS API）
- 模型：DeepSeek-V3/R1、Qwen-Max/Turbo
- 向量库：Dify 内置 Weaviate（非 PGVector；原 PGVector 选项已弃用）
- 客服检索阈值：0.65（低于该值触发未解答捕获与转人工）
- 客服 Dataset：CS_KB
- 销售 Dataset：Sales_KB

## 四、业务黄金闭环
1. To-C 智能客服：用户提问 -> 检索 CS_KB -> 命中>=0.65 自动回答；命中<0.65 转人工并写入 core_unanswered_questions。
2. To-B 销售 Copilot：销售输入客户痛点 -> 检索 Sales_KB -> 生成 3 种话术；成交后可提炼案例上报。
3. 数据自进化：Admin 审核 core_unanswered_questions 补答案 / 审核 core_sales_cases -> 触发 Sync Engine -> 写入 Dify Vector DB -> Agent 智商提升。

## 五、安全合规（不可协商）
- 客服 Agent 严禁给出疾病诊断和具体用药建议。
- 高风险关键词（便血、剧烈腹痛等）强制转人工。
- 涉及肠菌机制、益生菌搭配、指标解读的内容需医师二次审核（DOCTOR 标签）。

## 六、案例提炼标准模板
销售提交成交案例时，AI 必须按以下结构输出：
- 客户类型
- 核心抗拒点
- 成交破阻逻辑
- 推荐跟进话术

## 七、接口契约（MVP 阶段）
- POST /api/v1/admin/knowledge/{item_id}/approve
- GET  /api/v1/admin/knowledge
- POST /api/v1/cs/unanswered/capture
- POST /api/v1/knowledge/submit

## 八、未确认/待运营决策项

- 医师审核权限账号体系（MVP 阶段可用 Admin 角色兼容）。
