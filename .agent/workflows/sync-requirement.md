# 需求变更与全局上下文同步工作流 (.agent/workflows/sync-requirements.md)

## 1. 触发场景
* 当用户在 `.agent/prompts/requirement_doc.txt` 中更新了任何业务需求时。
* 当用户在对话中提出了新的硬性技术指标或业务变动时。

## 2. Agent 自动化执行步骤 (硬性红线)
当你检测到上述触发场景时，**严禁仅在对话框中回复“我知道了”**，必须无条件顺序执行以下链条：

1. **增量提取**：精炼读出新需求中的【核心权益】、【计费变动】、【技术硬指标】。
2. **同步大纲**：立刻调用工具打开根目录的 `AGENT.md`：
   * 将提取出的核心变动更新至 `## 1. 项目基本盘 (Project Context)` 的最新业务确认中。
   * 修改 `## 6. 动态记忆区 (Session Memory)` 的 `⏰ 最近一次同步时间`，精确到分钟（格式：YYYY-MM-DD HH:mm）。
3. **关联校验**：检查新需求是否与现有的 `.agent/rules/security.md` 或 `ui-ux.md` 冲突。如有冲突（例如：从原定的“试看3分钟”变成了“不能试看”），必须同步修改对应的规则文件。
4. **向用户交账**：修改完成后，向用户汇报：“已自动将最新需求同步至 AGENT.md 第 1 章与第 6 章，请检查本地文件变动。”
