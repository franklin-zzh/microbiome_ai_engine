# 产品需求文档 · agent_cs（原 gut-health-agent-platform）

# 肠道微生态 AI 智脑引擎 MVP 方案设计

### 面向“肠菌检测+调养”业务的闭环 Agent 矩阵与自进化知识底座系统架构及业务确认备忘录

为了在最短周期内搭建起一套具备**高专业度、数据自进化、能够同时赋能客服与销售**的 AI 引擎，本方案基于 MVP（最小可行性产品）理念设计。解耦大模型绑定风险，将核心聚焦在“中央数据控制”、“知识审核闭环”与“人机协同（Human-in-the-Loop）”上，为未来的医师 CDSS 辅助诊断及 GraphRAG 预留无缝扩容空间。

## 一、 业务闭环与用户黄金路径

系统打破传统孤立 Chatbot 模式，构建“前台场景化 Agent 触达 $\rightarrow$ 中台未解答/案例捕获 $\rightarrow$ 后台审核入库 $\rightarrow$ 知识库自进化”的黄金闭环：

Plaintext

```
[ 前端场景触达 ]                              [ 中台捕获/上报 ]                    [ 后台自进化闭环 ]

1. To-C 智能客服 ──(检索匹配 < 0.65)──> 2. 捕获未解答问题 (CS_GAP) ──┐
                                                                       ├──> 4. Admin 审核/补充标准答案 ──> 5. 触发 Sync Engine 同步至 Dify Vector DB
2. To-B 销售 Copilot ──(成功成交案例)──> 3. 提炼说服案例 (SALES_CASE) ─┘
```

- **To-C 智能客服路径**：用户在小程序/公众号提问 $\rightarrow$ Agent 检索 `CS_KB` 向量库。若匹配成功，自动高质回复；若答不上来，触发兜底提示，引导转接企微专属销售，并**自动将缺口问题异步写入后台待办**。
    
- **To-B 销售 Copilot 路径**：销售在企业微信侧边栏输入客户痛点或聊天记录 $\rightarrow$ Copilot 基于 `Sales_KB` 生成 3 种破冰/异议处理话术；针对成功成交对话，销售点击“提炼案例”，系统自动结构化提取“抗拒点+说服逻辑”并上报。
    
- **数据自进化路径**：管理员在 Web 后台一键审核通过缺口答案与销售案例，系统触发同步 Hook，调用 Dify API 增量写入向量库，Agent 智商实时提升。
    

## 二、 极简技术架构设计（解耦、低成本、快速交付）

采用 **“中央关系型数据库（源头） + 异步同步引擎（Sync Engine） + Dify 无状态 Agent 消费”** 的解耦架构。即使未来更换 Agent 编排平台，核心知识资产也永不丢失。

```
                     ┌─────────────────────────────────────────┐
                     │     中央控制台 (FastAPI + Vue/React)    │
                     └────────────────────┬────────────────────┘
                                          │
                                          ▼
┌───────────────────────────────────────────────────────────────────────────────────┐
│                           【核心数据底座 (PostgreSQL)】                            │
│  ┌─────────────────────────┐  ┌─────────────────────────┐  ┌───────────────────┐  │
│  │     knowledge_items     │  │  unanswered_questions   │  │    sales_cases    │  │
│  │  (客服 FAQ / 销售 SOP)  │  │   (客服未解答问题捕获)  │  │  (销售实战案例)   │  │
│  └─────────────────────────┘  └─────────────────────────┘  └───────────────────┘  │
└─────────────────────────────────────────┬─────────────────────────────────────────┘
                                          │ 审核通过 Hook (status -> APPROVED)
                                          ▼
                            ┌───────────────────────────┐
                            │   向量同步引擎 (Sync Engine)│
                            └─────────────┬─────────────┘
                                          │ API 写入
                                          ▼
┌───────────────────────────────────────────────────────────────────────────────────┐
│                         【Dify Agent 向量检索层 (Vector Store)】                   │
│         ┌──────────────────────────────┐     ┌──────────────────────────────┐     │
│         │   CS_KB (客服 Q&A 匹配库)    │     │ Sales_KB (销售话术/案例库)   │     │
│         └──────────────┬───────────────┘     └──────────────┬───────────────┘     │
└────────────────────────┼────────────────────────────────────┼─────────────────────┘
                         ▼                                    ▼
               【To-C 智能客服 Agent】                 【To-B 销售 Copilot Agent】
```

### 技术栈推荐

- **底座 API & 核心服务**：Python (FastAPI) + PostgreSQL（管理知识状态与流水）。
    
- **Agent & RAG 编排**：Dify (Docker 私有化部署或 SaaS 版 API) + DeepSeek-V3/R1 或 Qwen-Max。
    
- **前端形态**：
    
    - 运营/审核后台：极简 Web 管理控制台 (Vue 3 / React)。
        
    - 销售终端：企业微信侧边栏 H5 插件。
        
    - 客服终端：H5 / 小程序内嵌 Chat 组件。
        

### 核心表结构 (DDL) 概览

1. `knowledge_items`：存储统一知识与话术，包含 `domain` ('CS'/'SALES'/'DOCTOR')、`source_type` ('MANUAL'/'CS_GAP'/'SALES_CASE')、`status` ('PENDING'/'APPROVED')、`vector_doc_id`。
    
2. `unanswered_questions`：捕获客服兜底记录（`user_query`, `context`, `status`）。
    
3. `sales_cases`：存储销售实战对话原文与 AI 提炼模版（`raw_chat_log`, `extracted_summary`, `status`）。
    

## 三、 亟需与运营、业务方确认的 5 大核心细节

技术架构落地方案已定型，但在医疗健康（肠道微生态）场景中，上线前必须与业务负责人（医疗合规专家）明确以下边界：

|**确认事项**|**潜在影响 / 风险**|**产品经理建议方案**|
|---|---|---|
|**1. 医学合规与客服安全护栏**<br><br>  <br>  <br><br>_(高优先级 / 合规风险)_|肠菌检测与调养涉及健康建议，AI 若给出明确诊断或用药建议极易引发法律纠纷。|设定严格 Guardrails。客服 Agent 设定系统级 Prompt：**严禁给出医疗诊断**。遇到高风险词（如“便血、剧烈腹痛”）自动输出免责声明并强行转接企微人工。|
|**2. 企微侧边栏与销售身份绑定**<br><br>  <br>  <br><br>_(技术关联 / 体验)_|销售 Copilot 需要嵌入企业微信，若账号未打通，无法记录是谁上报了优秀案例，也无法做团队权限隔离。|MVP 阶段采用企微自建应用 H5 挂载侧边栏，通过企微 JS-SDK 获取当前登录销售的 `UserId`，实现静默登录与案例归属绑定。|
|**3. 知识审核权责划分**<br><br>  <br>  <br><br>_(运营关联 / 质量控制)_|销售提交的案例或客服补全的答案，如果没有专业人士把关就直接入库，会导致“垃圾数据污染知识库”，后续给错回复。|后台设两级审核机制：普通客服 FAQ 由运营审核；**涉及肠菌机制、益生菌搭配、指标解读的知识，强制打上 `DOCTOR` 标签，需由团队医师一键审核后再同步入库**。|
|**4. 客服未解答阈值 (Threshold) 设定**<br><br>  <br>  <br><br>_(技术与运营)_|相似度阈值设得太高（如 0.85），客服频繁转人工，体验差；设得太低（如 0.4），AI 会胡乱回答，产生幻觉。|MVP 阶段设为 **0.65**（Q&A 模式）。低于 0.65 即判定为缺口，异步写入 `unanswered_questions` 并给出友好转接提示，后续根据运营数据动态调优。|
|**5. 案例萃取标准模版**<br><br>  <br>  <br><br>_(业务策略)_|销售粘贴的聊天记录五花八门，如果 AI 提炼无统一标准，其他销售在 Copilot 检索时无法快速复用。|统一约束提炼输出结构为：`【客户类型】+【核心抗拒点】+【成交破阻逻辑】+【推荐跟进话术】`，保证知识库内案例的高度标准化。|

> **2026-08-03 更新**：产品方向演进为「微信 AI 客服平台」（微信客服/公众号/H5/企微群 + Dify + 5 秒异步网关 + 对话日志湖）。
> 本 PRD 的知识审核闭环（approve → Sync → Dify）、低分捕获、医疗安全规则 **继续复用**，为 v2 的子能力。
> 完整 v2 方案与 6 周计划见 `.agent/designs/wechat-ai-cs-v2.md`，评审意见见 `.agent/design-review.md`。

### v2 相对 v1 的新增能力
1. 四大微信入口（企微微信客服单聊、公众号/服务号、H5、企微群机器人），统一走 FastAPI 网关。
2. Redis 会话状态机（`NORMAL / HUMAN_MODE / BLOCKED`）+ 5 秒异步回包（第 3 周 Celery 队列）。
3. 三张新表：`chat_logs`（全量对话日志湖）、`session_state`（会话状态）、`leads_preview`（线索预备）。
4. 知识库四库结构：Standard FAQ / Product / Procedure / Marketing（双轨 RAG：FAQ 高阈值 + Product 混合检索）。
5. 满意度收集、用户画像、高频 Q&A 总结、企微线索通知。
